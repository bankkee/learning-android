# บทที่ 05 — State management

> **สถานะ: โครงของบทเรียน** ยังไม่มีบทสอนเต็มและยังไม่มีโค้ดตัวอย่าง ใช้สอนไม่ได้จนกว่าจะเขียนเพิ่ม

- **ที่มาของหัวข้อ:** senior: "State management"
- **ทำไมต้องเรียน:** หน้าจอจริงมีมากกว่าหนึ่งสถานะ และการจัดการผิดทำให้เกิดหน้าจอค้างหรือ dialog เด้งซ้ำ
- **ต้องรู้ก่อน:** บทที่ 04
- **เรียนจบแล้วไปที่:** บทถัดไป

## เรียนจบแล้วทำอะไรได้

- ออกแบบ state ของหน้าจอเป็นค่าเดียวที่ขัดกันเองไม่ได้
- แยกได้ว่าอะไรคือ state และอะไรคือเหตุการณ์ครั้งเดียว

## เนื้อหา

- state ของหน้าจอคืออะไร และ "แหล่งความจริงเดียว"
- ทำไมตัวแปรแยก `isLoading`, `data`, `error` ถึงเป็นปัญหา
- sealed class สำหรับ state: Loading / Success / Error (ตรงกับ `Response` ใน workshop)
- การ render: function เดียวที่แปลง state เป็นหน้าจอ
- เหตุการณ์ครั้งเดียว (แสดง dialog, เปิดหน้าใหม่) กับปัญหา LiveData ส่งค่าซ้ำหลังหมุนจอ
- state ที่ต้องรอดจาก process ถูกปิด: `SavedStateHandle` ระดับรู้จัก
- state ของฟอร์ม: ค่าที่ผู้ใช้พิมพ์, การ validate, การเปิดปิดปุ่ม
- **ต้องยืนยันกับ senior**: ขอบเขตของคำว่า state management ที่ตั้งใจให้สอน

## ตัวอย่างที่จะใช้สอน

หน้าจอที่มีปุ่มโหลดข้อมูลปลอม แสดงครบสามสถานะ และมี dialog ที่ต้องไม่เด้งซ้ำเมื่อหมุนจอ
